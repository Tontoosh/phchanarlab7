## E — Дүгнэлт (debrief)

Одоогийн нотолгоогоор Fed-Ex аялал тоолуурын зөрүү (BUG-01), давхардсан ном (BUG-03), зөвшөөрөгдөөгүй он (BUG-06) гэсэн өгөгдлийн асуудлуудыг илрүүлсэн тул үндсэн урсгалын хувьд хамгийн үр дүнтэй байв.
Couch Potato аяллаар хоосон гарчиг, зохиолч, оныг хүлээн авдгийг ажиглаж, нэг шаардлагын хувилбарууд учраас BUG-02-т нэгтгэсэн.
Supermodel аяллаар оны таслалтай дүрслэл (BUG-04), ногоон устгах товч (BUG-05) илэрч, харагдаж буй холбоосыг дагахад хуучин хувилбарын алдаатай хуудас (BUG-08) ажиглагдсан.
Saboteur аяллын буруу JSON туршилтыг зөв curl командаар давтахад HTTP 400-ийн оронд 200 буцаж, BUG-09 нь UI-ээс тусдаа API согог болох нь батлагдсан.
BUG-07-ийн анхны зураг дангаараа хангалтгүй байсан тул шинээр асаасан апп дээр Clean болон clean хайлтыг харьцуулж, үсгийн хэмжээ ялгаж байгааг хоёр screenshot-оор баталсан.
Charter нь UI, өгөгдөл, холбоос, API-ийг хамарсан тул одоогийн нотолгоонд charter-аас гадуурх олдвор гэж ялгах зүйл байгаагүй.
Урт текстийн хүснэгт, бутархай он, 1000 ба 2100 зааг, зохиолчийн хайлт болон устгалын дараах мессежийг бүрэн шалгасныг нотлох баримт үлдээгүй тул дараагийн charter-т эдгээрийг оруулна.
Лаб 1-ийн бодит тестийн кодтой тулгаагүй боловч шаардлагатай assertion нэмбэл Playwright нь хоосон оролт, давхардал, тоолуур, оны формат ба муж, хайлт, холбоосын алдааг автоматаар барих боломжтой.
Устгах товчийн өнгийг хүний нүдээр шууд анзаарч болох ч CSS эсвэл visual assertion-тай автомат тест мөн шалгах боломжтой тул зөвхөн хүн олдог согог гэж дүгнээгүй.
API-ийн буруу JSON хариуг curl эсвэл API автомат тестээр шалгах боломжтой бөгөөд UI-ийн үндсэн алхмуудыг шинээр асаасан апп дээр баталгаажуулж, session-ийн нийт хугацааг тестерийн мэдээлснээр 60 минут, үе шатны задаргааг ойролцоо хувиар тэмдэглэсэн.
